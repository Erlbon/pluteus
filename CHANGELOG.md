# Changelog

Release notes are taken from the section of the tagged version (`## 0.5.0 ...`).

## Unreleased
- **Finding out why a stream is spotty.** The admin relay box now shows, for each open stream, the rate and two kinds of stall: *source stalls* (the stream itself went quiet for over a second before it reached pluteus: the provider or Dispatcharr) and *slow browser link* (pluteus had the data but the connection to the listener took over a second to take it: upload speed, the proxy). With debug logging on, each relayed stream also leaves one line when it ends (length, average rate, how long the source took to answer, the stall counts). The channel page has a **Stream info** button: the speed the data arrives at, how much is buffered, dropped frames, picture size, and how often and how long playback waited for data.
- **The "Connecting…" message sits in the middle of the picture** on the channel page, no longer over the play button.
- **Clearer config errors for the two commonest slips.** A setting written twice in one table (TOML says "Cannot overwrite a value") now also says so in plain words and how to fix it (a list such as `relay_allow` goes in ONE line), and a config pasted with curly quotes says that TOML needs straight quotes.
- **A whole playlist in one go.** In the TV picker, "Tick all listed" ticks every channel of the list (not only the first 150 shown), and saving sends them in batches of 200 (one save request takes at most 300 and used to drop the rest without saying so). Channel names that repeat are numbered ("NRK 1 2") instead of the later one being skipped. Checked in a browser with a 450-channel playlist: 450 files saved.
- **Clearer wording on Settings, My streams.** The field and the error say what is wanted: the stream's server, the part of the address between `https://` and the first `/`, and that the login is sent only there.
- **Add one channel by its address** in the TV picker (name and address, for example a Dispatcharr `/proxy/ts/stream/...` address): it joins the list ticked, and is saved like any other channel.
- **A station file with a TS address opens as a channel even without the marker** (`pluteus-kind="tv"`): addresses ending in `.ts`, `.mpegts` or `.m2ts`, or with `/proxy/ts/` in the path (Dispatcharr) are channels, so a playlist file saved by hand or by another tool no longer opens on the radio page.
- **MPEG-TS channels (Dispatcharr and other IPTV panels).** A channel whose address is not HLS (for example `http://host/proxy/ts/stream/<id>`) now plays: the channel page and the player bar use mpegts.js (vendored, Apache-2.0, 1.8.2, about 270 KB, loaded only when a TS channel is opened; the bar keeps the sound only). When the browser cannot read the stream directly (plain http on an https page, no CORS) it goes through the relay (`...?i=N&ts=1`), which carries the transport stream under the same limits, counts and Stop as radio, and with `relay_allow` can reach a panel on your own network. Needs H.264/AAC (HEVC channels fail, with the usual "did not start" message). "Test ticked" in the TV picker says "play to try" for these (an endless stream cannot be tested by a fetch). Verified in a browser with a real H.264/AAC transport stream: picture and time advance on the page, through the relay, and in the player bar after leaving the page.
- **Importing an IPTV playlist (Dispatcharr and the like).** The TV picker has an "Import a playlist" section: choose an M3U file, or (relay on) give its address and the server fetches it. The channels are listed like search results; tick some and save: one `.m3u` file each in IPTV, with name, logo, group and guide id. Channels saved by the TV picker now say `pluteus-kind="tv"`, so a channel whose address does not end in `.m3u8` (an MPEG-TS stream such as Dispatcharr's `/proxy/ts/stream/...`) opens on the channel page.
- **`relay_allow` (config).** A list of exact `"host:port"` strings that pluteus may fetch from even on a private address or an unusual port (the relay, station logos and the playlist fetch), for a media server on your own machine, for example `relay_allow = ["192.168.1.99:9191"]`. Everything not listed keeps the public-address-only rule. See SECURITY.md.
- **An app key in the OPDS address, for reader apps that cannot log in.** `<site>/k/<app key>/opds` opens the catalogue as the key's user with no login: the PocketBook Android app sends no login to this server, whatever is typed in its boxes. Every link in the feed carries the key (folders, covers, downloads, comic pages), so the app can walk and download. Read-only like the key itself, only the paths a feed links to are reachable this way (no web pages, uploads, admin, Subsonic or WebDAV), a wrong key is refused and counted like a wrong password, revoking the key ends every address that holds it, and the key is masked in the access and debug logs. The admin page shows the address when a key is made. See SECURITY.md.
- **OPDS Authentication Document.** A 401 on an `/opds` address now also carries the small JSON document that newer reader apps look for (`application/opds-authentication+json`, Basic login with "User name" and "Password" labels). Without it some apps (the PocketBook Android app) say "authorisation error" and never send the login. The Basic challenge stays in the header, so a browser still shows its login box.
- **The Basic login challenge carries only the realm** (no optional `charset="UTF-8"`): a reader app that parses the challenge itself can fail on the extra part and then never send a login (the PocketBook Android app sent none). Debug lines also list the names of the other request headers.
- **Debug mode.** The admin page has a Debug tab: switch on debug logging for 15 minutes (it switches itself off), read what the site was asked, clear the lines, and download a diagnostics text (version, settings summary, the lines) for a bug report. Each line says what was asked (names of query parameters only), the answer, who asked, and for a login its kind and what could be said about it (lengths, whether the name matches a user, why it was refused). `debug = true` under `[server]` keeps it on all the time. Each line also says how long the answer took, its content type and size, and the HTTP version, which is what shows a slow or oddly shaped answer. Never recorded: passwords, keys, cookie values, query values. See SECURITY.md.
- **A reader app's login now tolerates a capitalised or padded user name.** E-reader keyboards often capitalise the first letter or add a space ("Erlend " for "erlend"). A Basic login name that matches exactly one user ignoring letter case and surrounding spaces now means that user (passwords stay exact, and two users that differ only in case are never guessed between). The login throttle counts every spelling against the same account.
- **The refusal log says more** about the usual slips: the password length and whether it has a space at the start or end or is empty (never the password).
- **Reader apps that send the name or password as Latin-1** (older firmware, for a password with ø, å or é) now log in: the Basic header is read as UTF-8 first, then as Latin-1.
- **Every refused Basic login is logged** with the name, the address and the reason (wrong password, no such user, header unreadable), never the password, so a reader app that "does not accept" its login can be diagnosed from the server log.
- **Fixed: tapping the speed text above the play button changed the speed.** The speed written along the top of the play button is now only a readout; the - and + beside the play button change it. A thumb reaching for play (or the title above it) can no longer switch the speed by accident.

## 0.9.8 - 2026-10-14
- **The TV picker and the relay.** With `relay = true` the TV picker leaves "https only" off by default (a saved plain-http channel plays through the server), says so, and "Test ticked" marks a channel that a secure page cannot test, or that a server refuses to show to a web page, as "via the server?" instead of "fails" (the relay does not need that permission).
- **Subsonic resume from the web player.** When no app has saved a queue (or the web player was used after it), `getPlayQueue` answers with the unfinished song you opened last in the web player, the rest of its folder after it, and the saved position. Nothing extra is stored.
- **Admin Stop for TV channels.** The relay box lists each streaming HLS channel with a Stop button: its playlist and pieces are refused for two minutes, so the player gives up (audio streams already had Stop).
- **Tk admin window:** the Users tab shows a Notes column and the access dialog has the "may write shared notes" checkbox.
- **Notes: the readers link to the note, and a single book's own description.** The EPUB and comic readers get an **About** link in their bar when the book's folder (or one of the three above it) has a note. A folder with no note that holds exactly one EPUB or CBZ shows the description written inside it (the EPUB's `dc:description`, the CBZ's `ComicInfo.xml` Summary).
- **The player bar joins the pluteus bar on wide screens.** From 1000 pixels wide the player's buttons and title sit in the same row as the pluteus bar (one bar instead of two); on a phone it stays a strip under the bar, as before.
- **TV mode.** For a browser on a TV: larger text and buttons, a clear focus ring, the remote's arrow keys move between buttons and links (Enter presses, Back goes back), and the bar and the page below it hand the focus to each other. Settings has "Turn on for this device" and "Turn off" (kept in that browser only; `?tv=1` or `?tv=0` on any address does the same). The readers and viewers keep their own arrow keys.
- **Subsonic: recently played and resume.** `getAlbumList2` / `getAlbumList` with `type=recent` lists the albums of the audio files you have a saved position in (nothing new is logged), and `savePlayQueue` / `getPlayQueue` keep one saved queue per user so another device can pick up where you stopped (an empty save clears it; it is deleted with the user).
- **Settings: "Forget my choices for single folders"** clears every List / Covers choice kept per folder.
- **A manual workflow for the Docker image** (`.github/workflows/docker.yml`): builds and smoke tests the image, and with "Publish" ticked pushes `ghcr.io/<owner>/pluteus:<version>` and `:latest` for amd64 and arm64. Never runs by itself.
- **Notes: the rest of round 1.** Front matter (`---` block with `title`, `tags` ...) is read for the page title and hidden; long documents get heading anchors (a copyable `#` link) and a contents list; `[[wiki links]]` find a file by name in the same folder, above it, or below the top of the library (no index; an unknown name stays plain words); the music player bar shows an **About** link to the nearest note about the artist, album or author; the Subsonic biography prefers a note you wrote yourself; `album.md` and `series.md` are recognised next to `artist.md`, `author.md` and `about.md`; `artist.nfo`, `album.nfo` and Calibre's `metadata.opf` are read as the folder's about text when there is no note.
- **Notes: editing in the browser.** An **Edit note** link on a folder's note (and **Add a note** on a folder without one), and an **Edit** button on a note's own page, open a text box with Preview, Save and Remove. A note about a library folder is saved as your own copy in your upload folder (`Notes/<library>/<folder>/`), seen only by you and winning over the library's note; a note in your own upload folder is edited in place. Safe by construction: only the note names, only `.md`, `.markdown` and `.txt` in your own folder, at most 64 KB, atomic write, your space limit, and a save is refused when the file changed since the page was opened. See SECURITY.md.
- **Notes: shared notes (opt-in).** `notes = "edit"` on a root plus the new per-user right `notes = true` (a **Notes** column on the admin Users page) let that user write a note into the library itself, for everybody; the editor then offers "my own note" or "a note in the library". Needs the library mounted read-write. Documented in `docs/notes-format.md` and `docs/library-layout.md`.
- **The relay, step R6: Subsonic radio list.** With `relay = true` and an upload folder, stations of the Radio folder that need the server (plain http, or a stored login) are listed with an address on this server (`/rest/stream?id=...`) carrying the music app's own key or token, so the app plays them through the relay with the same limits and Stop. https stations keep their own address; a login that arrived as a plain `p` password is never copied into an address.
- **The relay, step R5: the admin view.** With `relay = true` the admin Status page has a Stream relay box: the key's source and fingerprint, the limits, every audio stream open now (user, station file and number, since when, bytes carried) with a Stop button that ends it, the TV channels streaming, bytes carried per user since the start, and how many streams each user has stored (counts only: the administrator still cannot read or use a stored login).
- **The relay, step R4: stored logins and headers for protected streams.** Settings > My streams (with `relay = true` and an upload folder) stores entries: a name, a login (user name and password) or a token, headers such as `Referer` and `User-Agent`, and the host names they may be sent to. A station file uses one with `pluteus-stream="Name"` on its `#EXTINF` line; that station then always plays through the server, which sends the login and headers to the listed hosts and to no other host (decided again at every redirect and for every piece of an HLS channel). Entries are encrypted in the state database (HMAC-SHA256 keystream plus an HMAC tag, standard library only) with `relay_key` from the config when set, otherwise a key pluteus creates in the data folder (`relay.key`); each entry records which key sealed it, so a changed key is reported and never fails silently. Only the user who stored an entry can use it; nothing stored is ever shown again, logged, put in a playlist token or echoed in an error; removing a user deletes their entries. Back up the data folder or keep the config key: entries cannot be recovered without it. See SECURITY.md.
- **The relay for TV channels (HLS), step R3:** a channel whose server a browser cannot reach directly (no CORS, or plain `http://` on an https site) now plays through the server, with `relay = true`. The player tries the channel directly first and switches to the server by itself when the stream fails (or goes straight there for a plain http channel on an https page), on the channel page and in the player bar's TV sound. The server fetches the channel's playlist and rewrites it: every address in it (variant playlists, segments, keys, maps) becomes a signed token that names that address for that user only and lapses after an hour, so a page can fetch only what the server offered and never an address of its own. Pieces are typed by what they contain, capped (30 MB), and limited per user; a channel holds a lease on the stream limit that each playlist refresh renews and that lapses when the player leaves. See SECURITY.md. Checked with a real stream: a 1080p channel played with every playlist and segment going through the server (9 segments fetched in the check), and no error.
- **Now playing for radio (needs `relay = true`):** a station that sends the title of the current song inside its stream (what DAB shows as the programme text; Icecast and Shoutcast call it ICY metadata) now shows it: the player bar reads `Artist - Title · Station`, the radio page shows the title under the station name, and the lock screen gets the artist, title and station. The browser cannot read that title itself, so the server asks the station for it with a short side connection (it opens the stream with `Icy-MetaData: 1`, reads up to the first metadata block, about 16 KB, and closes): the audio still plays directly and is not carried by the server. The player asks every 20 seconds while a station plays; answers are kept for 10 seconds so any number of listeners cost one look-up, and at most four look-ups run at once. The same address guard as the relay applies and the station is named by file and number, never by address. A station that sends no title, or only its own name, leaves the bar as it was. Checked against live stations: SomaFM shows artist and title, NRK P3 its programme text.
- **The stream relay, first step (off by default):** with `relay = true` in `[server]`, a radio station a browser cannot play directly goes through the server: a plain `http://` station on your https site, or a stream whose server refuses the browser. The player tries the direct stream first and switches to the server by itself when it fails (the bar then says "via the server"); a plain http station on an https page goes straight through it. Only for users with an upload folder, and only for a station of a station file the user can open: the page names the file and the number of the station (`/relay/<library>/<file>?i=N`), never an address. The server checks the address like the logo fetch does (plain http or https, no password in it, every address the name resolves to must be public, the connection goes to the checked address, at most three redirects each checked again), ends a stream that stalls for 15 seconds, accepts only an audio reply (a web page or an HLS playlist is refused with a reason) and states the audio type itself; nothing of the source's headers is passed on. At most `relay_streams_user` (default 2) streams per user and `relay_streams_total` (default 6) in all are open at once; one more gets a clear "too many" answer. The admin Services box shows it. TV channels (HLS), stored logins, headers and the now-playing title are the next steps (see docs/ROADMAP.md). Checked with a real stream: it played through the server with the position advancing.
- **Shuffle on folder pages:** next to Play all there is a **Shuffle** button that plays the same kind of list in random order in the player bar. A folder (below the one you pressed Shuffle in) that holds an empty marker file named `noshuffle.txt`, `noshuffle` or `.noshuffle` is left out together with everything under it, and `.m4b` audiobooks are never included; Play all is unchanged and still plays everything. Press Shuffle inside a marked folder and it plays that folder. (A minimum song length, to keep short sound effects out, comes with the full random mix: it needs the song lengths.)
- **Settings: Play all and Shuffle on a folder:** include the folders below it (the default, as before) or only the files in that folder.
- **Folder notes (first slice of the notes item):** a folder page shows a note about the folder itself, as rendered Markdown by the same safe renderer as any `.md` page: **`artist.md`, `author.md` or `about.md`** (the first found) at the top, and **`README.md` or `index.md`** at the bottom, like GitHub. Only on the first page of a folder; a file that is too big, binary or unreadable is skipped. Nothing is shown when there is none. Write them with any editor; the folder markers apply as always.
- **Subsonic artist biography:** `getArtistInfo2` and `getArtistInfo` answer with the text of the artist folder's `artist.md`, `artist.txt` or `about.md` (Markdown marks removed, at most 4000 characters), so Tempo and other apps show it. No online look-up. Empty when there is no note, as before.
- **DOS-style ASCII art (`.nfo`, `.diz`, `.asc`):** when such a file is not UTF-8, the viewer now reads it in the old DOS character set (code page 437) instead of guessing Windows-1252, so the block and box-drawing characters of scene art show as drawn (the footer says `cp437 (DOS)`); the lines are set tight so the blocks join up. A UTF-8 `.nfo` (the kind Kodi writes) and every other file keep their old behaviour. Also behind "show as text anyway".

## 0.9.7 - 2026-10-14
- **Tidier station folders:** the picture beside a station file (`NRK P3.png` next to `NRK P3.m3u`) is no longer listed as a file of its own, in `Radio`, `IPTV` or any folder; it is the station's cover. It asks the server which station files in your `Radio` or `IPTV` folder have no picture beside them, takes the logo address from the file's `tvg-logo` attribute or finds it in the directory by the stream address (radio-browser for radio, the iptv-org catalogue for TV), and the server fetches each one through the guarded fetch (40 per request) and saves it beside the file, naming it in a `.m3u` that did not. - **Radio in the player bar has a link back:** like a TV channel's Picture link, a radio station playing in the bar has a **Station** link to its page.
- **Station and channel logos:** the radio and TV pickers send each station's logo (radio-browser's favicon, iptv-org's logo list), and the server downloads it once (guarded: public web addresses only, size and time limits, checked as a real picture and rewritten small) and saves it beside the file as `Name.png` or `.jpg`; the `.m3u` also keeps a `tvg-logo` attribute (Kodi reads it). A picture of the same name put next to a station file by hand counts too. The logo is the cover of the radio page, sits beside the channel name on the TV page, shows on the left of the player bar, and gives the station file a real tile in the cover view. Nothing is fetched when you browse. See SECURITY.md.
- **List or Covers is remembered:** the List / Covers switch on a folder page used to apply to that page only; now the choice is saved (the same setting as in Settings) and holds in every folder. A Settings option decides how far it reaches: **every folder** (the default) or **that folder only**, so some folders can stay covers and others lists; a folder with no choice of its own follows the general one set in Settings. (At most 500 folders are kept.)
- **Live channel player:** the round play button sits closer to the LIVE row. The music and movie players keep room above it for the playback speed; a live channel has no speed, so that gap was empty.

Without the script the video keeps the browser's own controls.

## 0.9.5 - 2026-10-14
- **TV picker** (`tools/tv-picker.html`, not part of the server): the channel catalogue of iptv-org (about 30,000 channels), filtered by country, category, name and quality (https, HLS, no streams that need a special header, no adult channels; geo-blocked streams, such as NRK from inside Norway, are shown with their label and can be hidden with a tick box), with a try-it button, a "test ticked" button (does the channel's server let a web page read it, the usual reason a channel will not play in pluteus), and saving as one `.m3u` file per channel into a library folder (optionally a folder per country) or as one list for Kodi. Needs Chrome or Edge for the folder save. Nothing is sent anywhere but the catalogue and the channels you try.
- **Live channels (IPTV, one channel per file):** a station file (`.m3u`, `.pls`, `.url`) whose stream address ends in `.m3u8` (HLS) opens in a video page instead of the radio page. The browser plays it itself where it can (Safari, iPhone, newer Android); elsewhere pluteus uses the vendored hls.js 1.7.3 (Apache-2.0, 620 KB, loaded only on that page, run without a worker). The channel name comes from the `#EXTINF` line; a file with several channels has a list. No guide, no recording. The stream's own server must allow playback from a web page (CORS) and must not be plain `http://` on an `https://` site; the page says so when a channel does not start. Only that page's content policy lets media and requests go to other servers. Tried against a public HLS test stream; not yet against a real channel list. Keep channel lists out of a top-level `Radio` folder (the Subsonic radio list).
- **The shell and a resident player (first version):** every signed-in page now opens inside a "shell" page: the pluteus bar on top, a slim player strip, and the site in a frame below. The audio lives in the shell, so a queue keeps playing while you browse folders and read books or comics. A folder page has a **Play all (N)** button that queues every audio file of the folder and the folders below it (up to 2000, in play order); the strip has previous, play/pause, next, the title, the position in the queue and a close button, plus lock-screen controls. A song started in a page's own player pauses the queue, and the other way round. The address bar, page title and light/dark follow the frame; opening a page directly (or reloading) lands in the shell at the same page; `?noshell=1` opts out. **Radio** plays there too: a station file opened in the shell hands its stations to the player strip (shown as "live"), so the radio keeps playing while you browse or read; pause leaves the broadcast and play rejoins it, and previous and next switch station. Not yet: a queue list, saved playlists, adding single files, and the player merged into the bar on wide screens. A login page that appears inside the frame (an expired session) is not yet taken out of it.
- **Admin link, only when reachable:** the Admin link starts hidden, and a small script asks this browser whether the admin address answers (a request that does not read the reply, two and a half seconds at most); only then is the link shown. With `admin_url` set, an administrator coming in from the public address used to get a link that opened an empty page; now it simply does not appear. A positive answer is remembered for five minutes in the tab. The page's content policy allows that one address in `connect-src`, nothing else.
- **Admin link:** the Admin link in the top bar opens in a new tab. The admin page is on its own port, which the browser treats as another site, so opening it in the same tab stopped a song that was playing; now the player tab keeps playing.
- **Subsonic internet radio:** `getInternetRadioStations` lists the station files (`.m3u`, `.pls`, `.url` with an http(s) stream) of a top-level `Radio` folder, in it and one folder down, so apps such as Tempo (and the car) show them as radio stations. The names come from the file (the `#EXTINF` name, else the file name); the list is kept for two minutes. Adding, renaming and deleting stations from an app is not supported: the files are the list.
- **Subsonic:** a folder named `Radio` at the top of a library (where you keep station `.m3u` files next to the music) is left out of the artist and album lists, so apps do not show it as an empty artist. A `Radio` folder deeper down is an ordinary folder.
- **Subsonic stars:** `star`, `unstar` and `getStarred2` use the user's Favourites shelf, so a heart tapped in an app is the same as the heart in the web pages, and starred songs and albums show the heart in the app. (Before, a star was ignored and the heart went away again.)
- **Subsonic lyrics:** OpenSubsonic `getLyricsBySongId` serves the timed lines of a `.lrc` file or tag, else the plain tag text; apps such as Tempo can show them.
- **Radio picker** (`tools/radio-picker.html`, not part of the server): a web page you open on your own computer. HLS (`.m3u8`) streams are not supported, and a plain `http://` station is blocked by the browser on an `https://` page (the player says so). A file with no stream address stays a text file.

### Review fixes
Security and stability fixes from a two-part code review of 0.8.8. No new features.
- **Secrets out of the log:** the access log no longer prints `p=`, `apiKey=`, `t=`, `s=` or `/join/TOKEN`; pluteus writes its own access line.
- **Logins by key:** a wrong key or token counts against the address only and never locks a user name; a correct key gets through while
  the name is locked for passwords; a stale key in a forgotten app can no longer lock its owner out of everything.
- **App keys are read only for real:** they can no longer write reading progress or bookmarks. Keys of users who were removed are deleted.
- **Request bodies** are read with a hard size limit (no buffering of whatever a client sends); odd characters in a token or key header
  give an error instead of a crash; the token login takes the same time for unknown names.
- **Thumbnails:** a picture is refused before it is decoded when it has more than 20 million pixels (a small file can hold a huge picture),
  only a few fixed widths are made, and three at a time.
- **Uploads:** a failed finish no longer leaves an empty file behind, and Windows retries a file that a virus scanner holds for a moment.
- **Player:** a reload or a restored tab of an auto-advanced file resumes where you stopped (the `?autoplay=1` flag is taken off the
  address); the arrow keys no longer fight the scrubber or the browser's Back.
- **Subsonic:** an empty `search3` lists the library (artists and albums, paged) as apps expect; albums carry `songCount`, `duration` and
  `created`, artists `albumCount`; music folder ids are whole numbers; lists that cannot be known (starred, by year ...) are empty; one album
  scan at a time and the cap holds for several libraries. Folder and file ids changed (they now start with `p`): apps re-read the library.
- **Favourites:** a long shelf costs no more than a short one (stops at 60 usable entries).
- README: where the app keys are stored.
